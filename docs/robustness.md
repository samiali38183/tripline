# Evasion sweep

Generated by `tripline robustness --markdown docs/robustness.md`. Do not edit by hand.

For each Linux scenario, `tripline/robustness.py` generates deterministic variants of the attack
command that stay the same attack and replays them through the scenario's rules. The variant
generators are plain Python lists and products (random combinations use seed 20261111); each
variant is a set of audit events, and a rule catches it when it matches at least one event.
Counts are *caught / variants the rule's logsource applies to*. "Any expected" is the share of a
family's variants caught by at least one rule the scenario expects. `cmdline` families keep the
same tool; the `alternative-tool` family reaches the same effect with another tool and is reported
separately.

**What this is not.** The lists are hand-written from shell and coreutils behaviour and are not
exhaustive; variants are evaluated at the event level and are not executed; the child event of a
wrapper is assumed to be recorded; shell quoting and whitespace are resolved before `execve`, so
they only change the wrapper event and shell builtins. A high catch rate is not proof of
robustness. A miss listed below is a documented gap, not a claim about every deployment.

**Headline:** 200 of 251 command-line variants caught by an expected rule across 3 Linux scenarios; 0 of 4 alternative-tool variants.
